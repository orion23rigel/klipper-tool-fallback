consistency.

<threat_model>
- Threat T-02-03: manual mutation corrupts canonical state, changes unrelated tool
  records, or routes to an unconfigured physical command. Mitigation: pure state-model
  helpers validate both endpoints against canonical state and rebuild through
  `_canonical()` without changing tool records or backups.
- Threat T-02-04: command-time persistence fails after in-memory publication, causing
  status and runtime routing to diverge from disk. Mitigation: save the complete candidate
  first, publish only after success, suppress no-op work, and translate failures to
  command errors.
- Threat: a user bypasses logical authorization during an active print. Mitigation:
  public `SELECT_PHYSICAL_TOOL` rejects both `printing` and `paused`; only private
  transition code may select physically during active jobs.
- Threat: physical bypass accidentally clears or rewrites logical ownership. Mitigation:
  bypass changes selected physical ownership only after success and never changes active
  logical ownership or persisted mappings.
- Threat: an active-route mapping change reaches the placeholder transition dispatch
  point before Plan 02-03 provides pause ownership and failure containment. Mitigation:
  fail closed during this plan by rejecting any active-print mutation that would change
  the active logical route, while allowing inactive-route changes and exact no-ops.
- No high-severity threat remains after canonical validation, command authorization, and
  save-before-publish controls.
</threat_model>
