<threat_model>
- Threat T-05-01: arbitrary dynamic notification detail injects a second G-Code command
  or breaks adapter parsing. Mitigation: construct parameters centrally in fixed order,
  use canonical safe tokens and `n/a`, sanitize unexpected detail to one ASCII
  safe-alphabet token, and bound it to 160 characters after sanitization.
- Threat T-05-02: notification failure, delay, recursion, re-entry, or duplicate terminal
  callbacks changes safety behavior or emits multiple outcomes. Mitigation: establish
  final state first, latch the generation's complete immutable finalized event before
  adapter invocation, reject/report any later non-identical event for that generation,
  guard delivery, reject extension-owned mutation/hardware commands during delivery,
  catch/report adapter failures locally, and never retry or promise delivery.
- Threat T-05-04: notification re-entry queues a mutation or queue draining changes the
  event context/outcome. Mitigation: reject backup commands during notification delivery,
  capture immutable terminal event context before delivery, attempt notification before
  draining, and keep drain failures subordinate to the completed outcome.
- Threat T-05-03: queue or notification integration bypasses save-before-publish.
  Mitigation: retain Plan 01/02 candidate persistence path unchanged and add regression
  assertions for failed save and exact no-op behavior.
</threat_model>
