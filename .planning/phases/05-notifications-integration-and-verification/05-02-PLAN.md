<objective>
Implement the discussion-approved queued mutation contract that supersedes old
reject-during-workflow research. Ensure accepted policy changes remain future-facing,
ordered, visible, and unable to change or mask active workflow outcomes.
</objective>

<threat_model>
- Threat T-05-04: queued mutation changes an active graph decision/transition, applies
  out of order, bypasses failed older work, or masks a terminal outcome. Mitigation:
  queue frozen validated operations, never retain `gcmd`, drain only after terminal
  outcome/transition exit, apply FIFO against latest state, stop and retain at first
  failure, and catch/report drain failures locally.
- Threat T-05-03: queued save failure publishes candidate state or a queued no-op
  writes. Mitigation: reuse Plan 01 save-before-publish application per distinct
  operation and count no-ops without saving.
- Threat: notification recursion joins the terminal queue batch. Mitigation: define
  draining to require notification delivery inactive and leave the explicit
  notification-before-drain integration point for Plan 03; backup commands invoked
  during notification delivery must eventually reject rather than queue.
- Injection-safe notification parameter construction is outside this plan; no dynamic
  notification transport is built here.
</threat_model>
