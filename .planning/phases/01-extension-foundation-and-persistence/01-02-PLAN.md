<objective>
Implement the versioned state model and failure-safe atomic JSON store that preserve all
routing and filament-state fields across restarts.
</objective>

<threat_model>
- Threat: malformed or tampered state routes logical tools to invalid physical tools.
  Mitigation: validate every schema type and cross-reference before exposing state.
- Threat: interruption during persistence corrupts the only state copy. Mitigation:
  same-directory temporary write, file flush/fsync, `os.replace`, and parent-directory
  fsync where supported.
- Threat: path replacement or symlink behavior writes outside the intended location.
  Mitigation: normalize the configured path, create only its parent directory, use an
  implementation-owned temporary filename in that directory, and never follow values
  found inside persisted JSON as paths.
- No high-severity threat remains after validation and atomic replacement controls.
</threat_model>

  <action>
Add reconciliation that preserves valid persisted fields, initializes newly configured
tools with `loaded=false`, `purged=false`, `failed=false`, configured backups, and
identity mappings, removes deleted tool records/logical mappings, removes deleted tools
from backup lists, and resets mappings targeting removed tools to identity. Existing
persisted backup order wins over configuration; configuration initializes backups only
for entirely new tool records. Existing schema-v1 records missing `backups` remain
invalid.

Add a store that expands and normalizes `state_path`, treats a missing file as
initialization, strictly decodes existing JSON, and writes only changed state. Atomic
writes must create a same-directory temporary file, write deterministic UTF-8 JSON with
a trailing newline, flush and fsync it, call `os.replace`, fsync the parent directory
where supported, and remove a surviving temporary file after failure.
  </action>
  <verify>
    <automated>python3 -m py_compile klippy/extras/tool_fallback_state.py</automated>
  </verify>
  <acceptance_criteria>
    <criterion>Reconciliation removes stale tools and stale backup references.</criterion>
    <criterion>Reconciliation resets a mapping whose physical target was removed to the logical tool's identity mapping.</criterion>
    <criterion>The store calls `os.replace` only after the temporary file has been flushed and fsynced.</criterion>
    <criterion>The store does not rewrite an unchanged canonical state.</criterion>
  </acceptance_criteria>
