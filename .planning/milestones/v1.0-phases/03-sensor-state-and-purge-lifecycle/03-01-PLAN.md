<objective>
Establish the durable state, configuration, fake-runtime, and graceful sensor-resolution
contracts required by Phase 3. Resolve the `PURGE_TOOL` recursion hazard before any
public purge command is implemented, while keeping live sensor authority explicitly
runtime-only and non-fatal at startup.
</objective>

<artifacts_this_phase_produces>
- Optional per-tool sensor configuration with explicit unknown-authority degradation.
- A distinct default configured purge adapter and fail-fast public-command recursion guard.
- Immutable loaded, unloaded, failed-runout, purged, and unpurged state candidates.
- Deterministic fake reactor timers and fake filament sensors for later Phase 3 tests.
- Ready-time sensor runtime records and read-only status fields.
</artifacts_this_phase_produces>

<threat_model>
- Threat T-03-01: unavailable sensor objects abort startup or silently present stale
  persisted filament state as verified. Mitigation: resolve with `lookup_object(name,
  None)`, validate status strictly, degrade to explicit unknown authority, preserve
  durable historical/operator state, and expose verification separately in status.
- Threat T-03-02: stale or wall-clock-dependent timer fakes make later debounce tests
  unreliable. Mitigation: add deterministic reactor registration, rescheduling,
  cancellation/NEVER semantics, and explicit ordered time advancement.
- Threat T-03-03: mutable or invalid filament/purge updates publish impossible or
  unpersisted state. Mitigation: central immutable candidates, exact no-op identity,
  invariant enforcement, unrelated-state preservation, and save-before-publish callers.
- Threat T-03-06: configured `purge_gcode: PURGE_TOOL` recursively calls the public
  lifecycle command. Mitigation: default to `_TOOL_FALLBACK_PURGE`, normalize and reject
  any adapter whose command token is `PURGE_TOOL`, and test the migration contract before
  public command registration.
- No automatic fallback traversal, heating, stage timeout, notification, or real-printer
  behavior is introduced by this plan.
</threat_model>
