<threat_model>
- Threat T-03-02: bouncing readings, repeated polling, or stale callbacks commit false
  loaded/runout state. Mitigation: one restartable timer per tool, generation/target
  checks, equal-reading non-extension, expiry re-read, and symmetric insertion/removal
  logic.
- Threat T-03-04: event hooks or explicit state commands directly execute fallback,
  mutate mappings, or resume a user-owned pause. Mitigation: limit them to candidate
  state updates and status/warnings; preserve all routes; never call fallback or resume.
- Threat T-03-05: an unavailable selected-tool sensor repeatedly pauses printing or
  falsely restores authority. Mitigation: acknowledge only after successful first pause,
  suppress repeats for the same outage, clear acknowledgement only after restored
  authority survives debounce, and never pause for inactive-tool outage.
- Threat: standard sensor immediate-pause ownership is ambiguous. Mitigation: do not
  auto-resume transient events in Phase 3; leave FALL-01 through FALL-03 completion to
  Phase 4.
- No backup traversal, fallback selection, heating, purge, notifications, timeout stages,
  or real-printer UAT is introduced by this plan.
</threat_model>

When a reading changes, replace the target, increment a generation/token, and schedule
expiry at the original observation plus configured `debounce_time`; repeated equal polls
must not extend the deadline. At expiry, re-read status and commit only if authority,
target, and generation still match. Use the same path after ready for startup
reconciliation. Reconcile loaded startup state so persisted loaded+loaded preserves
purged while clearing failed as required, newly confirmed loaded is unpurged/non-failed,
and confirmed unloaded clears loaded/purged. Persist every changed candidate before
publication; status exceptions or authority loss cancel stale confirmation without
clearing durable facts.
