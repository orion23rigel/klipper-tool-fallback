Establish the fail-closed runtime foundation for Phase 4: explicit standard-sensor pause
ownership, transient recovery, pure recursive backup resolution, and a visible
runtime-only workflow checkpoint. Keep heater and complete fallback stage execution for
later waves.
</objective>

- JSON-safe runtime workflow checkpoint/status and conflict guards.

<threat_model>
- Threat T-04-01: paused print state is mistaken for extension ownership, causing a
  user-owned pause to auto-resume or fallback to begin before confirmation. Mitigation:
  strict integer ownership parsing, selected-tool/active-context/paused validation,
  separate pending ownership across debounce reversal, and no fallback before confirmed
  failed-runout persistence.
- Threat T-04-02: recursive graphs loop forever, skip reachable descendants, or trust
  live authority instead of durable eligibility. Mitigation: pure ordered DFS,
  path-local loop detection, scan-local duplicate suppression, traversal through
  ineligible intermediaries, persisted loaded/non-failed eligibility, and one fresh
  canonical re-scan before exhaustion.
- Threat T-04-03: stale callbacks or conflicting operations replace an active workflow,
  leak non-JSON-safe runtime objects, or imply restart recovery. Mitigation: one
  generation-checked runtime-only checkpoint, explicit conflict rejection, JSON-safe
  snapshots, and no checkpoint fields in schema v1.
- No heating, physical fallback selection, fallback mapping persistence, external
  notifications, or real-printer UAT is introduced by this plan.
</threat_model>
