<objective>
Add the `with_user_defined_backup(logical, backup)` mutation method to `FallbackState` and its test suite. This is the foundational state mutation API that Phase 9 commands will call to define and undefine backup mappings (D-15).

Phase 8 added the `user_defined_backups` field but did not add a dedicated mutation method. The existing `with_mapping` and `with_backups` methods are the pattern to follow.

Purpose: Provide the state mutation primitive that DEFINE_TOOL_BACKUP and UNDEFINE_TOOL_BACKUP commands will invoke. Without this method, the commands cannot mutate user-defined backups. Per D-22, user-defined backups are stored in `self.state.user_defined_backups` as a `MappingProxyType` dict. Per D-23, the state mutation must return a new `FallbackState` instance (frozen dataclass pattern).

Output: New `with_user_defined_backup()` method on `FallbackState` + 6+ test cases covering happy path, no-op, self-reference rejection, unknown tool rejection, and None (undefine) behavior.

    **Signature:** `def with_user_defined_backup(self, logical, backup):`
    - `logical`: canonical tool name (str) — the tool getting a user-defined backup
    - `backup`: canonical tool name (str) or None — the backup tool to assign, or None to remove

    **Behavior:**
    1. Validate `logical` is a configured tool (reuse `_require_tool(logical)` or inline check against `self.tools`)
    2. If `backup` is not None, validate it is a configured tool (reuse `_require_tool(backup)` or inline check)
    3. If `backup` is not None, reject self-reference: `logical == backup` → raise `StateValidationError`
    4. No-op detection: if the current `self.user_defined_backups[logical] == backup` (handling None for missing keys), return `self`
    5. Build new dict: `new_udd = dict(self.user_defined_backups)`, then either set `new_udd[logical] = backup` or `del new_udd[logical]`
    6. Return `self._canonical(self.tools, self.mappings, new_udd)` — this creates the frozen MappingProxyType

    **Placement:** Add after `with_tool_unpurged()` (around line 310) and before `_require_tool()` (line 313). Keep mutation methods grouped together. Per D-24, this method should be added to `FallbackState` if not already present (Phase 8 added the field but not mutation methods).

    **Pattern reference — `with_mapping` (lines 196-208):**
    - Validates both endpoints exist in `self.tools`
    - No-op check: `self.mappings[logical] == physical` → return self
    - Builds new dict, calls `self._canonical(self.tools, mappings, self.user_defined_backups)`
    - Returns canonical (frozen) result

    **Pattern reference — `_validate_user_defined_backups` (lines 319-330):**
    - Already validates self-references and unknown tools — our method can do inline validation for single-entry changes, and the save() path will call `_validate_user_defined_backups` as a final gate

    **No-op detection (D-16):** If the state doesn't change (e.g., defining the same mapping that already exists), return `self` — same pattern as `_apply_immediate_backup_operation`. This avoids unnecessary disk writes.

    **Do NOT:** Modify `_validate_user_defined_backups()` — that's called at save boundary and handles full-dict validation. This method does single-entry validation.
