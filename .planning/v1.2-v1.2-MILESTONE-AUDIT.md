### End-to-End User Flows

**Flow 1: User defines backup for undefined tool**
1. G-code calls undefined tool Tn → Phase 10 detects, pauses print, displays prompt
2. User runs `DEFINE_TOOL_BACKUP Tn Tm` → Phase 09 validates, persists mapping
3. Sentinel cleared → Phase 11 resumes print
4. Later, Tn selected → Phase 12 resolves backup graph with UDD as first candidate
5. UDD Tm tried → Phase 12's fail-closed safety checks apply
6. **Status: COMPLETE**

**Flow 2: User does not respond (timeout)**
1. G-code calls undefined tool Tn → Phase 10 detects, pauses print, displays prompt
2. Timeout expires → Phase 11 auto-defines mapping to first configured tool
3. Mapping persisted via Phase 08 state store → Phase 09 command logic
4. Print resumes → Phase 12 backup resolution includes the auto-defined mapping
5. **Status: COMPLETE**

**Flow 3: UDD fails, falls through to configured backups**
1. User defines UDD Tn → Tm via Phase 09
2. Tn selected during print → Phase 12 resolves, tries UDD Tm first
3. Tm fails (unloaded/failed) → Phase 12 fail-closed safety skips it
4. Configured backup chain tried next → Phase 12 existing logic
5. **Status: COMPLETE** (verified by tests: `test_user_defined_backup_fails_then_configured_used`, `test_user_defined_backup_unloaded_then_configured_used`)

**Flow 4: SHOW_TOOL_FALLBACK_STATE observability**
1. User runs `SHOW_TOOL_FALLBACK_STATE` → Phase 12
2. `get_status()` calls `self.state.to_dict()` → Phase 08 serialization
3. Output includes `user_defined_backups` key → Phase 12 verification
4. **Status: COMPLETE**

## 6. Deviations from Plan

### Phase 10: Scope Expansion (significant, positive)
Phase 10 subsumed the full prompt flow (pause, display, wait, timeout fallback) that was originally split across Phases 10 and 11. The original plan (D-11) stated Phase 10 would create a checkpoint and return, letting Phase 11 handle the prompt. Instead, Phase 10 implemented the complete `_handle_undefined_tool_prompt` method synchronously.

**Impact:** Phase 11's scope was substantially simplified since the core prompt flow was already implemented in Phase 10. Phase 11 still added test coverage and config validation. This consolidation is a net positive for simplicity and user experience.

### Phase 12: No code change for observability
Phase 12 Plan 02 (SHOW_TOOL_FALLBACK_STATE observability) required no code changes because `get_status()` already included `user_defined_backups` via `state.to_dict()`. This was confirmed during implementation.
